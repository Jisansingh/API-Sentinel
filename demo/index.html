Security findings & risk scores — GET /api/findings

Findings are not stored. Each call recalculates them over a rolling 60-second window ending at each client's most recent request, so a burst older than 60 seconds disappears once newer traffic arrives. Sentinel's own routes (health, inventory, findings, alerts, scan) are never captured, so this page's polling does not count as traffic; only generated sample traffic does.

Persistent alerts — POST /api/scan · GET /api/alerts · PATCH /api/alerts/{id}

Alerts are stored and deduplicated; only "Run scan" creates or updates them. The Sentinel admin key is added server-side by the local proxy (serve.py), never by this page.
